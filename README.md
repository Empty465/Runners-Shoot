# Runner's Shoot

## 1. 프로젝트 개요

**Runner's Shoot**는 Unity 6로 개발하는 **2D 플랫포머 슈팅 패링 액션
게임**이다.

주인공은 **총과 검(카타나)**을 사용한다.

-   총: 원거리 공격
-   검: 방어, 패링, 근접 공격
-   적: 기계 계열의 여러 종류
-   기본 진행: **전투 → 플랫포머 → 전투 → 플랫포머**
-   전투는 일반 전투와 정해진 방에서 진행되는 아레나 웨이브 전투로
    구성한다.

게임플레이의 참고 방향은 **Doom: The Dark Ages - Revelations**와
**SANABI: A Haunted Day DLC**이다.

> 이 README는 게임 디자인과 개발 방향을 확인하기 위한 기준 문서다. 전체
> 게임을 한 번에 구현하는 명령서가 아니다. 개발은 작은 기능 단위로
> 나누어 구현하고 각 단계마다 직접 검증한다.

## 2. 개발 원칙

### 2.1 구현 방식

-   Unity 6 + C#을 기본으로 사용한다.
-   MCP를 이용해 Unity Editor 작업을 수행할 수 있다.
-   핵심 게임플레이 로직은 C# Script로 구현한다.
-   Unity Inspector에서 조정해야 하는 수치와 설정은 가능한 한
    `SerializeField`로 노출한다.
-   게임플레이 데이터와 로직을 분리할 필요가 있는 경우
    ScriptableObject를 사용한다.
-   PlayerController 하나에 모든 플레이어 기능을 넣지 않는다.
-   Enemy도 하나의 거대한 스크립트로 만들지 않는다.
-   각 시스템은 가능한 한 독립적인 책임을 갖도록 구성한다.

### 2.2 기존 시스템 보호

새로운 기능을 구현할 때 현재 정상적으로 작동하는 시스템을 불필요하게
재작성하지 않는다.

기존 시스템을 수정해야 하는 경우 최소한의 변경만 수행한다.

특히 다음 항목은 특별한 이유가 없는 한 기존 구조를 유지한다.

-   Player 이동
-   기존 Input System 설정
-   기존 Prefab 구조
-   이미 검증된 Enemy 공격 시스템
-   Package 설정
-   Project Settings
-   SampleScene

### 2.3 작업 진행 방식

새로운 기능을 구현하기 전에:

1.  현재 Scene과 관련 Prefab을 확인한다.
2.  관련 C# Script를 읽는다.
3.  기존 시스템과 연결되는 지점을 확인한다.
4.  필요한 변경 범위를 간단히 정리한다.
5.  구현한다.
6.  Unity Console Error와 C# 진단 오류를 확인한다.
7.  Play Mode에서 가능한 범위까지 직접 테스트한다.
8.  변경된 파일과 테스트 결과를 보고한다.

한 번에 지나치게 많은 시스템을 구현하지 않는다.

# 6. 플레이어 메커니즘

## 6.1 이동

-   WASD로 이동한다.
-   SPACE로 점프한다.

## 6.2 체력

플레이어는 **체력(HP)**과 **아머(Armor)**를 가진다.

### HP

-   HP가 0이 되면 사망한다.
-   필드 내 아이템을 획득하거나 적을 처형할 때 회복할 수 있다.

### Armor

-   Armor가 존재하면 피해를 받을 때 HP 대신 Armor가 감소한다.
-   Armor가 1이라도 있으면 HP 감소를 방지한다.
-   필드 내 아이템 또는 기타 경로를 통해 획득할 수 있다.

------------------------------------------------------------------------

# 7. 패링

플레이어는 우클릭으로 검을 한 바퀴 휘둘러 패링한다.

-   패링 가능한 공격을 막을 수 있다.
-   모든 방향에서 오는 패링 가능 공격을 패링할 수 있는 형태를 목표로
    한다.
-   한 번 패링한 뒤 약간의 딜레이가 있어 연속 입력으로 패링 꼼수를
    막는다.
-   패링 시 게임에 약 1초 정도의 슬로우가 걸린다.
-   패링 성공 시 강화 포인트를 획득한다.
-   범위 내 일반 등급 적은 즉시 처리할 수 있다.
-   그보다 높은 등급의 적에게는 약간의 피해를 입힌다.

현재 프로토타입에서는:

``` text
우클릭
 ↓
ParryHitbox 활성화
 ↓
Enemy AttackHitbox와 충돌
 ↓
Parry 성공
 ↓
Enemy 공격 취소
 ↓
Enemy Stun
```

까지 구현되어 있다.

# 8. 회피

Shift로 현재 누르고 있는 좌우 방향으로 빠르게 대시한다.

-   좌/우 방향으로 대시한다.
-   공중에서도 사용할 수 있다.
-   패링 가능한 공격을 회피하면 적에게 경직을 주지는 않는다.
-   대신 패링과 같은 효과를 얻는다.
    -   슬로우
    -   강화 포인트 획득

------------------------------------------------------------------------

# 9. 강화 포인트

플레이어는 **강화 포인트**를 충전할 수 있다.

획득 방법:

-   패링 성공
-   회피 성공
-   기타 게임플레이 보상

강화 포인트를 소모하여:

- R키로 현재 들고 있는 총기를 10초 동안 강화한다. 강화 1회에 1포인트를 소모하며, 강화 중 다시 R키를 누르면 중첩되지 않고 지속 시간만 10초로 갱신된다. 시간이 끝나면 기본 상태로 돌아온다.
-   E를 길게 눌러 강화된 근접 공격을 사용한다.

# 10. 총기

총기는 마우스 커서 방향을 기준으로 조준한다.

SMG는 좌클릭을 누르고 있는 동안 연속 발사하며, Shotgun과 Railgun은 클릭당 한 번 발사한다.

총기 종류:

1.  SMG
2.  Shotgun
3.  Railgun

`1`, `2`, `3` 키로 총기를 교체한다.

각 총기에는 별도의 탄약이 존재한다.
HUD에는 현재 총기의 탄약과 강화 단계가 표시된다.

## 10.1 SMG

-   연사 속도가 빠르다.
-   기본 피해는 약하다.
-   총알 투사체를 발사한다.
-   기본 탄약은 30발이다.

강화 효과: **과열**

-   사격 속도 증가
-   피해량 소폭 증가
-   명중한 적을 불태움
-   적에게서 소량의 Armor 획득

## 10.2 Shotgun

-   연사 속도가 느리다.
-   한 번에 7개의 탄이 약 26도 범위로 퍼진다. 투사체들은 서로 충돌하지 않고, 적이나 장애물에 맞거나 비행 시간 3초가 끝날 때까지 날아간다. 속도 16 기준 최대 사거리는 약 48 게임 단위다.
-   총알 투사체를 발사한다.
-   기본 탄약은 8발이다.

강화 효과: **연사**

-   탄약 2발을 사용해 두 번째 사격을 빠르게 이어서 발사한다.
-   이후 다시 딜레이를 갖는다.
-   피해량이 약간 증가한다.
-   유사 더블배럴 방식
-   탄약이 1발만 남으면 한 번 발사할 수 있다.

## 10.3 Railgun

-   연사 속도가 매우 느리다.
-   강력한 피해를 준다.
-   히트스캔 빔을 발사한다.
-   기본 탄약은 4발이다.

강화 효과: **폭발**

-   적 또는 벽에 닿은 지점에서 소규모 폭발을 발생시킨다.
-   강화 중 폭발 범위와 피해량이 증가한다.

# 11. 근접 공격

근접 공격에는 별도의 **근접 공격 포인트**가 존재한다.

-   근접 공격 포인트는 천천히 자동 충전된다.
-   패링 또는 회피 성공 시 더 빠르게 충전된다.

## 일반 근접 공격

E를 눌러 검에 에너지를 둘러 전방의 적을 공격한다.

-   적에게 명중하면 근접 공격 포인트를 소모한다.
-   적에게 피해를 준다.
-   소량의 탄약을 획득한다.

## 처형

기절 상태이며 체력이 30% 미만인 적에게 근접 공격을 사용하면 처형한다.

처형 시:

-   적을 즉사시킨다.
-   대량의 탄약 획득
-   체력 획득

## 강화 근접 공격

근접 공격 포인트가 모두 충전되어 있을 때 E를 길게 누르면 강화된 근접
공격을 사용한다.

적에게 명중하면:

-   근접 공격 포인트를 모두 소모한다.
-   더 큰 피해를 준다.
-   다수의 적에게 광역 스턴 효과를 줄 수 있다.

# 13. 적 메커니즘

적은 모두 기계 계열이다.

적은 HP를 가지고 있으며 HP가 0이 되면 사망한다.

## 적 상태

### 대기

-   전투 시작 전 상태
-   플레이어가 전투 영역에 들어오기 전
-   가만히 있는다.

### 전투

-   플레이어를 쫓아간다.
-   공격권에 따라 직접 공격하거나 포위한다.

### 사망

-   HP가 0이거나 처형당하면 사망한다.
-   잔해/시체 형태가 된다.
-   공격과 행동을 하지 않는다.

### 경직

-   갑자기 큰 피해를 입거나 기타 요소로 발생한다.
-   잠시 이동과 공격을 멈춘다.

### 기절

-   기본 조건: HP가 30% 이하
-   긴 시간 동안 공격과 이동을 멈춘다.
-   근접 공격으로 처형할 수 있다.
-   처형되지 않고 시간이 지나면 다시 이동과 공격이 가능하다.
-   처형 시 탄약과 체력 아이템을 드롭한다.

> 개발 시 `경직(Stagger)`과 `기절(Stun)`을 서로 다른 상태로 관리한다.
> 현재 구현된 Parry 성공 → Enemy Stun은 이후 적 등급별 규칙과 연결할 수
> 있도록 확장 가능하게 만든다.

# 14. 적 등급

보스를 제외하면 세 가지 등급이 존재한다.

## 일반

-   패링 공격을 하지 않는다.
-   이동 속도가 느리다.
-   별도의 기절 효과를 받지 않는다.
-   우클릭으로 휘두르는 공격에 즉사할 수 있다.
-   체력을 드롭할 수 있다.

종류:

### 슬래그

-   많이 손상된 안드로이드
-   플레이어에게 천천히 접근한다.
-   공격 속도가 느림

### 폰

-   일반적인 안드로이드
-   슬래그보다 이동/공격 속도가 빠르다.
-   플레이어보다는 느림
-   패링 불가능한 느린 원거리 투사체를 발사
-   사격 거리를 유지하고 플레이어가 너무 가까이 오면 물러난다.

## 중급

### 나이트

-   양팔이 블레이드인 전투 드로이드
-   원거리 공격 없음
-   플레이어에게 빠르게 접근하여 패링 가능한 근접 공격을 시도
-   패링을 1회 당하면 경직

### 아처

-   팔 대신 라이플 하나를 장착
-   근접 공격 불가
-   플레이어와 거리를 벌림
-   원거리에서 빠른 패링 가능 투사체를 발사

## 고급

### 바론

-   나이트의 강화 개체
-   높은 체력
-   더 빠르게 플레이어에게 패링 가능한 근접 공격
-   거리가 멀어지면 패링 가능한 원거리 공격을 사용한 뒤 다시 접근

고급 등급은 경직을 3회 이상 받아야 경직되는 규칙을 목표로 한다.

현재 AI 프로토타입은 적별 감지 범위, 이동 속도, 교전 거리, 후퇴 거리,
체력과 공격 설정을 사용한다. 역할 색상과 이름 표시로 종류를 구분한다.
`BasicEnemyController`의 Archetype 설정에서 `Slag`, `Pawn`, `Knight`,
`Archer`, `Baron` 중 역할을 선택한다.
TestArena에서는 다섯 Archetype이 자동 배치되고 머리 위에 테스트용 이름이
표시된다.
공격권을 공유해 동시에 공격하는 적 수를 제한하는 시스템은 아직 별도 작업이다.

등급이 높을수록:

-   기본 체력 증가
-   공격력 증가
-   전투 난이도 증가

# 15. 적 공격 경고

패링 가능한 공격을 사용할 때에는:

``` text
공격 준비
    ↓
경고 표시
    ↓
공격
```

의 흐름을 사용한다.

현재 BasicEnemy 프로토타입에서는 공격 준비 시 경고 표시와 AttackHitbox
활성화가 구현되어 있다.

# 16. 적 공격권

적들은 공격권을 공유한다.

### 공격권이 없는 적

-   플레이어 근처를 어슬렁거린다.
-   플레이어를 포위한다.
-   직접 공격하지 않는다.

### 공격권이 있는 적

-   플레이어에게 직접 접근한다.
-   근접 또는 공격 사거리에 들어와 공격을 시도한다.

### 공격권 우선순위

공격권은 다음 조건을 고려한다.

-   플레이어와 가까운 적
-   높은 등급의 적

공격권은 주기적으로 갱신한다.

# 17. 아레나 전투

정해진 방에서는 아레나 형식으로 적들이 웨이브 방식으로 소환된다.

전투 흐름:

``` text
아레나 진입
    ↓
전투 시작
    ↓
Wave Spawn
    ↓
적 처치
    ↓
다음 Wave
    ↓
...
    ↓
상위 등급 적 전부 처치
    ↓
남은 일반 등급 적 즉사 처리
    ↓
전투 종료
```

Arena 시스템은 일반적인 Level 시스템과 분리한다.

예상 책임:

``` text
ArenaCombat
├─ 전투 시작
├─ Wave 관리
├─ Enemy Spawn
├─ 공격권 관리
└─ 전투 종료 판정

Level
├─ 플랫폼
├─ 이동 구간
├─ 방 전환
└─ Arena 진입/퇴장
```

하나의 거대한 GameManager에 모든 기능을 넣지 않는다.

# 19. 시스템 설계 방향

권장 구조:

``` text
Player
├─ PlayerController
├─ PlayerParry
├─ PlayerHealth
├─ PlayerCombat
├─ PlayerWeapon
├─ PlayerDash
└─ PlayerResource

Enemy
├─ BasicEnemyController
├─ EnemyAttack
├─ EnemyHealth
├─ EnemyStun
├─ EnemyMovement
├─ EnemyState
└─ EnemyRank
```

공통 전투 시스템은 필요에 따라 다음과 같이 분리한다.

``` text
Combat
├─ AttackData
├─ DamageData
├─ ParryData
├─ IDamageable
├─ IParryable
└─ 기타 공통 전투 인터페이스
```

구체적인 구조는 구현 과정에서 현재 코드와 충돌하지 않는 범위에서
결정한다.

# 20. 개발 단계별 제한

각 작업에서는 **현재 작업에 필요한 시스템만 구현한다.**

예를 들어:

``` text
현재 작업: Player HP + Damage

구현:
- Player HP
- Enemy AttackHitbox → Player Damage
- HP 감소
- HP 0 처리

이번 작업에서 구현하지 않음:
- Armor
- Execution
- Gun
- Ammo
- HUD
- Dodge
- Slow Motion
- 강화 포인트
```

새로운 시스템을 만들면서 미래 시스템까지 미리 구현하지 않는다.

# 21. MCP / AI 개발 규칙

Unity MCP를 통해 Editor 작업을 수행할 때 다음 규칙을 따른다.

### 작업 전

-   현재 Scene 확인
-   관련 GameObject 확인
-   관련 Component 확인
-   관련 Script 확인
-   기존 구조와 충돌 여부 확인

### 작업 중

-   필요한 파일만 생성/수정
-   기존 정상 시스템 최소 변경
-   생성한 Component의 Inspector 설정 확인
-   Prefab과 Scene의 차이를 확인

### 작업 후

다음 항목을 확인한다.

``` text
- C# 진단 오류
- Unity Console Error
- 관련 Component 연결
- Scene 저장
- Prefab 저장
- Play Mode 동작
```

MCP에서 시간 진행이나 물리 시뮬레이션을 완전히 검증할 수 없는 경우에는
그 한계를 명확하게 보고하고, Editor에서 사용자가 직접 확인해야 하는
항목을 구분한다.

# 22. Git / 프로젝트 공유

프로젝트는 GitHub를 통해 데스크톱과 노트북에서 공유한다.

Unity Scene도 Git에 포함되어야 한다.

특히 다음 파일은 Git에 포함한다.

``` text
Assets/Scenes/Gameplay/TestArena.unity
Assets/Scenes/Gameplay/TestArena.unity.meta
```

Unity의 `Library`, `Temp` 등 재생성 가능한 폴더는 Git에 올리지 않는다.

Scene을 변경한 경우 해당 `.unity` 파일과 `.meta` 파일이 Git 상태에서
추적되는지 확인한다.

# 23. 현재 개발 목표

현재 가장 중요한 목표는 최종 게임의 모든 기능을 빠르게 만드는 것이
아니라,

**플레이어가 실제로 재미있는 전투를 수행할 수 있는 핵심 전투 루프를 먼저
완성하는 것**이다.

핵심 루프:

``` text
이동
 ↓
적 발견
 ↓
총으로 공격
 ↓
적의 공격 경고 확인
 ↓
패링 / 회피
 ↓
강화 포인트 획득
 ↓
적 경직 / 기절
 ↓
근접 공격
 ↓
처형
 ↓
체력 / 탄약 회복
 ↓
더 강한 적과 전투
```

이 핵심 루프가 충분히 검증된 후 무기 종류, 적 종류, 아레나 웨이브, UI,
연출, 실제 스테이지를 확장한다.
